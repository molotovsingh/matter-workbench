## New findings (this delta)

**N1 — Tester identity now ships off-VM in "safe" telemetry mode — F22 widened. P2 risky\* (product call, make it explicit).**
The feedback route injects the authenticated user into feedback context server-side (`routes/app-shell-routes.mjs:105-107`), `sanitizeContext` whitelists `username`/`displayName`/`userRole` (`services/private-beta-feedback-service.mjs:279-284`), and `buildSyncPayload` normalizes-and-keeps context (`:229-236`) — so the mothership POST now carries a person's login and display name alongside the matter name F22 already flagged. Verified end-to-end; the auth-routes test explicitly asserts the attribution (`test/private-beta-auth-routes.test.mjs`). This is deliberate (the operator inbox shows a sender, and server-side injection means it can't be spoofed when auth is on) — but for a legal product, names of *firm staff* tied to *matter names* leaving the VM is a privacy posture decision that should be written down, not inherited from an inbox feature. **Fix:** document the decision next to the telemetry-mode docs; or strip `displayName` from the sync payload (keep it ledger-local) and let the mothership key on `username` only.

**N2 — The forgiving-feedback contract is now implemented twice — a fresh T7 seed planted by a fix-wave. P3.**
Client `buildPrivateBetaFeedbackDraft` (`react-ui/src/lib/privateBetaFeedback.ts:15-26`) and server `normalizeFeedback` (`private-beta-feedback-service.mjs:146-153`) both encode "choice defaults to `did_not_work`, summary falls back across fields" — and they already disagree at the margin: the server additionally falls back to `context.visibleError`; the client doesn't know that rule. Defense-in-depth on a real boundary is fine (server stays authoritative), but this is exactly the client/server twin shape that produced F10. **Fix:** keep, but add the missed-by-one-side test: a server-accepts/client-rejects fixture pair so drift surfaces in CI.

**N3 — `telemetry-sync-client.mjs` has no direct unit test. P3.** The module that now owns every egress deadline is tested only through its three consumers, none of which exercise the timeout branch or the AbortController fallback. **Fix:** a small `test/telemetry-sync-client.test.mjs` with a hanging fake fetch asserting the abort fires.

**N4 — Deployment-pack HTTPS phase clobbers `/etc/caddy/Caddyfile` unconditionally. P3.** `scripts/private-beta-deployment-pack.mjs:196` emits `… | sudo tee /etc/caddy/Caddyfile` with no backup or existing-config guard. Fine for a dedicated beta VM; destructive on any host already running Caddy. **Fix:** emit a `test -s /etc/caddy/Caddyfile && cp …bak` line first, or write a site file under `/etc/caddy/conf.d/`.

**N5 — Loopback-HTTP readiness exception verified fail-closed (strength, with one nit).** `isLoopbackHttp` (`scripts/private-web-beta-readiness-check.mjs:235-248`) allowlists exact hosts (`localhost`, `127.0.0.1`, `::1`, `[::1]`) and rejects everything else — other `127/8` addresses fail toward HTTPS-required, the right direction. Nit: in no-auth mode the feedback route's identity fallback accepts client-supplied `username`/`displayName` (`app-shell-routes.mjs:105-107` `||`-chain) — spoofable attribution, but only where attribution is meaningless anyway. No action.
