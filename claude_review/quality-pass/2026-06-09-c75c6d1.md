#### `matter-rerun-advice-service.mjs` — ⚠️ brittle* (P1 partial)

🔻 **Mtime fallback fires for zero-mtime records.** `:116-122`:

### New P2s

#### F1 — `runtime-db-configurable-skill-store.mjs:51-58` — 🔻 brittle (T8)

🔻 **`updateStore` writes the pre-mutation store object, not the mutator's result.** `runtime-db-configurable-skill-store.mjs:51-58`:
```js
const store = await readStoreWithFingerprint();  // reads store A
const result = await mutator(store);              // mutator receives store
await writeStore(store, { expectedCatalogFingerprint: store.catalogFingerprint });
```
`writeStore` receives `store` (the pre-mutation object). If the mutator returns a new structure via `result` without mutating `store` in place, the write persists the original unmodified catalog — silently losing the intended change. The contract (mutate `store` in-place) is enforced by convention, not by code.

**Fix:** Change `:57` to `await writeStore(result ?? store, { ... })`. This respects a returned value while still handling mutators that modify `store` in-place and return `undefined`.

#### F2 — `runtime-db-storage-service.mjs:1482-1496` — 🔻 brittle (T8)

🔻 **Tombstone on file deletion is incomplete — `extraction_records` and `source_descriptors` stay live.** `runtime-db-storage-service.mjs:1482-1496` (`materializedFileTombstoneSql`) sets `storage_objects.state = 'deleted_pending'` and `matter_artifacts.is_current = false`, but does not touch `extraction_records` or `source_descriptors`. After a file is deleted from the materialized directory, the workspace view drops it (because `storage_objects.state` is now `deleted_pending`), but structured rows in those tables continue to reference the deleted object. Downstream queries that JOIN against `extraction_records` or `source_descriptors` without checking `storage_objects.state` will return data for deleted files.

**Fix:** Add tombstone steps inside `persistMaterializedDeletions` for `extraction_records` (set `is_current = false` where `storage_object_id` matches) and `source_descriptors` (same pattern), matching the existing `matter_artifacts` tombstone at `:1487-1496`.

#### F3 — `services/private-beta-auth-service.mjs:244-256` — ⚠️ risky* (T5)

⚠️ **Synchronous file read on every session validation request.** `services/private-beta-auth-service.mjs:244-256` — both `authenticate` and `refreshSessionUser` call `readPrivateBetaUsersFile(usersFile)` on every invocation (`readFileSync` + JSON parse). The startup read at `:241` validates file readability but its result is discarded. Under concurrent traffic, if the file disappears or is momentarily unreadable between calls, every active session check throws a 503. #### F5 — `runtime-db-configurable-skill-store.mjs:38-49,150-167` — ⚠️ brittle*

### P3s (new — watch)

#### `runtime-db-storage-service.mjs:455-512` — write-race on same matter (P2 watch → T1/T6)
`runMaterializedMatterWrite` has no matter-level advisory lock. Two concurrent calls on the same matter (e.g., two parallel `/extract` requests) will both read the same initial state; the second writer will silently overwrite the first's persisted rows. The add-files allocation lock (F3) only guards `next_file_number`; it does not protect the full read-snapshot-mutate-write cycle. Low risk in current single-user CLI model; escalate to P2 refactor if multi-user concurrency is intended.

#### `runtime-db-configurable-skill-runs-service.mjs:29` — unbounded `transientRuns` cache
`transientRuns = new Map()` is never pruned. For a long-lived server process this grows without bound. Low practical risk given session-scoped use; worth a TTL eviction if session duration grows.

#### `scripts/private-vm-rollback.mjs:77` + `private-vm-rsync-deploy.mjs:103` — unvalidated release/commit name
Both scripts accept a release name or commit from env/CLI and interpolate into remote shell commands via `shellQuote`. `shellQuote` prevents injection; a path-traversal value (`../../../etc`) would be quoted and passed literally, but could traverse into arbitrary directories on the VM. **Fix:** Validate against `/^[a-zA-Z0-9_.-]{4,80}$/` before building the plan.

#### `scripts/private-vm-rollback.mjs:98-110` — partial-failure leaves symlink ahead of service
The `activate_rollback` step is `ln -sfn <target> <current> && systemctl restart <service>`. If `systemctl restart` fails, the `current` symlink already points to the rollback target while the service is down. Rerunning is the recovery path. **Fix:** Add a comment or failure note making this explicit — e.g., "if this step fails, the symlink has already been updated; restart the service manually."

#### `listofdates/contracts.mjs:1-4` — inverted dependency
`contracts.mjs` imports `EVENT_TYPES` and `LAWYER_FACING_PERSPECTIVE` from `providers.mjs` — a schema module importing from an HTTP client module. These constants are domain contracts and belong in `contracts.mjs`. **Fix:** Move both constants to `contracts.mjs` and re-export from `providers.mjs` if still needed there.

#### `listofdates/entries.mjs:140` — dead second parameter
`normalizeNarrativeText(value)` is declared with one parameter but called with two at four sites (`:65, :66, :134, :150`). The second arg is silently dropped. Not a current bug; would trap a future refactor that adds `sourceText` handling.

#### `private-beta-auth-service.mjs:229,253` — case normalization inconsistency
`readPrivateBetaUsersFile` normalizes usernames to lowercase on load (`:229`); `refreshSessionUser` compares session usernames with `secureEqual` (byte-exact match, `:253`). If the stored session username casing differs from the canonical form, the session is silently invalidated.

#### `react-ui/CommandPanel.tsx:294` — feedback `route` field is always "/"
`route: window.location.pathname + search` always returns `/` for this SPA. **Fix:** Use `state.activeTab + '/' + state.activeView` for a meaningful route value in feedback records.

#### `scripts/private-beta-users.mjs:115-135` — double read of users file
`readStore` calls `readFile(expandedPath)` and `readPrivateBetaUsersFile(expandedPath)` on the same file in sequence. A concurrent write between the two reads would produce a corrupt merge. **Fix:** Pass the raw JSON string to the service parse function rather than the file path on the second call.

## Emerging themes

Themes discovered from findings — numbered as established in prior runs, new theme added.

- **T1 — DB seam debt.** `matter-status-service` and `matter-store` payload-shape drift unchanged. New manifestation: `runtime-db-storage-service.mjs:455-512` — the materialized write cycle has no matter-level advisory lock, so concurrent DB-mode runs on the same matter can clobber each other. The seam between "atomic allocation" (locked) and "full materialized write" (unlocked) is the current boundary risk.

- **T2 — Mtime coupling.** One survivor: `matter-rerun-advice-service.mjs:116-122`. Content-aware primary path is added and correct; the mtime fallback still fires for zero-mtime Postgres records. One guard addition at `:121` closes this P1.

- **T4 — Policy/heuristic treadmill.** One survivor: `entries.mjs:172` (`Skyline'?s`). The decomposition removed many heuristic clusters; this one survived. Single-line fix.

- **T5 — Secret handling.** The most persistent theme — has a new P1 member. Three findings span two surfaces: `testConnection` error unredacted (`ai-settings-service.mjs:125`), `--password` CLI arg (`private-beta-users.mjs:183`), and per-request sync file read in auth service (`private-beta-auth-service.mjs:244`). Root pattern: credential/key handling is addressed where flagged but not applied as a consistent convention across new surfaces.

- **T6 — Concurrency unevenness.** `upload-service` cleared (per-root queue added). New instance: `runtime-db-storage-service.mjs:455-512` — allocation is locked but the full materialized write cycle is not. The locking convention exists but is applied narrowly.

- **T7 — Duplicated-contract drift.** `route-utils.mjs` extraction cleared the primary triplication. New seed: `hasRuntimeDbWritePath` is identically defined in `matter-workflow-routes.mjs:401` and `skill-factory-routes.mjs:198`. P3 watch; escalate when a third file needs it.

- **T8 — Write-path integrity (NEW).** Four findings share a root: multi-object write operations that don't treat all their targets as an atomic unit, leaving structured state in a partial or inconsistent condition when they partially fail or race. `F1` (updateStore writes pre-mutation store) · `F2` (tombstone incomplete for extraction_records) · `runtime-db-storage-service` materialized-write race (P2 watch) · `rollback` symlink/service split (P3). Root cause: each write operation treats its own target as atomic but doesn't account for the other structured objects that must change in the same logical transaction.

**Meta-observation:** Risk still concentrates at the **write boundary** — not in reads, not in business logic, but at the points where multiple structured objects must change together. T8 is the new organizing frame; it connects DB-layer findings (tombstone gap, updateStore bug) to ops-layer findings (rollback split state) through the same root cause.

## What it does well

- **`withMatterWriteQueue` is the right serialization primitive.** `upload-service.mjs:151-161` — promise-chain per key, `.catch(() => undefined)` ensures queue always advances on failure, acquired and released without explicit lock objects. Template for T6 fixes elsewhere: apply this pattern to `runMaterializedMatterWrite` for the same serialization guarantee.

- **Atomic DB write wrapping is consistent.** `runtime-db-sql-safety.mjs:25-34` + `wrapRuntimeDbWriteTransaction` — every DB write batch goes through `BEGIN/COMMIT`; the guard SQL is always prepended; test coverage at `test/runtime-db-sql-safety.test.mjs` enforces the invariant. This is the correct architecture for Postgres-backed operations; the tombstone gap (F2) is a gap in coverage, not a gap in the mechanism.

- **`shellQuote` is applied consistently in deploy scripts.** `private-vm-rollback.mjs:248-250` — every user-supplied value that touches a remote shell command is single-quoted and escaped. No shell injection risk found in either deploy script. This is the right convention for SSH-based ops tools.

- **Content-hash staleness primary path.** `matter-rerun-advice-service.mjs:332-429` — the new `findSourceDescriptorContentChange` / `findListOfDatesContentChange` paths are the right design: comparing immutable content hashes from artifact JSON survives filesys copies and Postgres migration. The mtime fallback is now the narrow residual; one guard closes the P1.

- **`normalizeStore` row-level fault isolation.** `private-beta-feedback-service.mjs:240-256` — malformed historical rows are isolated without dropping the whole ledger. This is the correct pattern for append-only diagnostic stores; use it as the template for any new JSON ledger service.
