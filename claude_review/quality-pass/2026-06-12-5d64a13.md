### New P1s (2) — both are twin-drift (T7) applied to the new auth/visibility layer

**F9 — `matter-store.mjs:39-48`: login scoping exists only in the runtime-DB twin; the auth + filesystem mode combination shares all matters across all logins. P1 risky.**
Commit `b543862` scoped matter visibility by login — in DB mode. `activeState()` falls back to a single shared `defaultState` whenever the runtime matter index is disabled (`matter-store.mjs:40`), and `listMattersHomeChildren` lists every directory unscoped (`:102-112`). Nothing couples the two env axes: `MWB_PRIVATE_BETA_AUTH=required` + filesystem storage boots fine (`private-beta-auth-service.mjs:20-22` and `runtime-db-matter-index.mjs:54-56` are independent), and in that shape every tester sees every client matter, all logins share one active-matter slot (user A's switch retargets user B's next workflow), and the matter-name ledger filters become no-ops. The only guard today is an *advisory* ops script (`private-web-beta-readiness-check.mjs:147`). Blast radius is cross-tenant confidentiality of legal matters; severity is P1 because the exposure is one plausible misconfiguration away and the fix is cheap. Independently flagged by two reviewers (storage + server batches). **Fix:** scope `activeState()` by username whenever `authEnabled` (not whenever the runtime index is enabled), **and** fail startup in `createWorkbenchServer` when auth is required but the runtime matter index is off; add a test for the combination.

**F10 — `react-ui/src/lib/lawyerMode.ts:25-27`: the client operator predicate is stricter than the server's, so default local (no-auth) mode loses the entire Settings surface. P1 brittle.**
Server semantics: auth disabled ⇒ full operator access (`isPrivateBetaSuperuserOrLocal`, `routes/route-utils.mjs:20-23`). Client: `canSeeOperatorSurface(user)` checks only `role === 'superuser'`, and in local mode `authUser` is null — so the Settings tab disappears (`ActivityBar.tsx:11,17`), SettingsPage is unreachable (`MainContent.tsx:181`), the technical-files toggle vanishes, and the tree gets lawyer-filtered even though the server returned everything. AI keys and matters-home become unconfigurable from the UI in the default local run — a functional regression introduced by `f9b6d6b`. `CommandPanel.tsx:110` already does it right (`!state.authEnabled || canSeeOperatorSurface(…)`), proving oversight rather than design; `authEnabled` was added to AppState in this very delta and five of six consumers ignore it. No test renders with `authEnabled: false`, which is why nothing caught it. **Fix:** make the predicate take `(authEnabled, user)` and return true when auth is disabled; add a local-mode visibility test.

### New P2s (the telemetry product and the seams it crossed)

**F11 — No egress deadline anywhere in the telemetry stack; one hung connection permanently stalls all draining.** Grep-verified zero `AbortSignal`/timeout across all four client services. `attemptSync` in metrics (`private-beta-metrics-service.mjs:145-153`), signal (`:231-239`), and feedback have unbounded `fetch`es; metrics additionally syncs *inside* its store-mutation lock (`:70,:126-133`, up to 100 sequential POSTs). The retry service's `running` re-entrancy guard (`private-beta-telemetry-retry-service.mjs:17`) then turns every future 5-minute tick into a no-op — a single hung (not refused) connection silently ends telemetry until restart. **Fix:** `AbortSignal.timeout(~10s)` on every sync fetch, move sync attempts outside store locks, add a per-tick deadline in the retry service.

**F12 — `private-beta-signal-service.mjs:136-137`: repeat-occurrence sync runs inline, awaited, in user request paths.** The delta (commit `d60b1ed`) re-syncs deduped signals by calling `attemptSync` inside `captureSignals`, which runs awaited inside `GET /api/jobs` and the matter-attention routes (`routes/app-shell-routes.mjs:81`). Verified consequences: a polling UI with any failed job fires one POST per failed-job signal per poll; with F11's missing timeout, a slow mothership adds minutes to a *user's* request (`safeCaptureBetaSignal` catches errors but still awaits); the network call holds the signal-store mutation lock. **Fix:** in the dedupe branch set `status:"queued"` and return — `syncQueuedSignals` + the 5-minute tick already handle exactly this.

**F13 — `mothership/store.mjs:241`: `new Pool(...)` registers no `pool.on("error")` handler — an idle-connection drop is an unhandled `error` event and kills the process.** systemd masks it on the VM at the cost of dropped in-flight requests; manual `mothership:serve` just dies. **Fix:** one line.

**F14 — `mothership/report.mjs:175-178`: report-side redaction lacks the postgres-URL pattern its sibling has (`http.mjs:44`), and the client-side signal sanitizer (`private-beta-signal-service.mjs:631-635`) has the same gap.** Signal payloads carry `details.errorMessage` straight from failed jobs; a DB error containing a connection string survives client sanitization, lands in jsonb, and prints verbatim into the operator report. Also `--format json` metric snapshots bypass redaction entirely (`report.mjs:144-148`). The redaction logic now exists in **five+ divergent copies** (mothership http/report/operator, signal, metrics, observability, retry) and only the metrics copy knows the product's own `mwb_ing_` token family. **Fix:** one shared redactor (the natural home `shared/secret-redaction.mjs` already exists) imported everywhere.

**F15 — `runtime-db-storage-service.mjs` is now a god-module in fact (2,093 lines), and its duplication has produced user-visible mode divergence.** `stageDefinition` (`:1224-1252`) duplicates `STAGE_DEFINITIONS` from `prepare-matter-service.mjs:8-44` minus the `/the_story` stage, and DB mode hardcodes `metadata: { missing: [], complete: true }` (`:392-395`) while the filesystem twin computes real missing-metadata — **the two storage modes give lawyers different prepare plans today.** Plus N+1 psql spawns per materialized read (`:491-503,:526-547`). **Fix:** extract the SQL builders (~700 pure-function lines) and the status/prepare logic into shared modules consumed by both twins; batch payload reads.

**F16 — `private-beta-auth-service.mjs` residual auth warts (risky\*):** (a) username-enumeration timing oracle — unknown/disabled users skip pbkdf2 entirely (`:247-248`); (b) login throttle keys on spoofable `x-forwarded-for` (`:406`) → bypass by header rotation, and each fake key grows `loginFailures` unboundedly (`:164-167`); (c) `resetPassword` doesn't invalidate live sessions (`:252-255`) — a compromised session survives a password reset for up to the 8h TTL. **Fix:** dummy pbkdf2 on miss; key the throttle on socket address absent a trusted proxy + cap the map; version sessions on hash change.

**F17 — `server.mjs` catch handler calls `sendJson` unconditionally; an error after headers are sent (mid-stream on `/api/file-raw`) makes `writeHead` throw inside the catch — an unhandled rejection in the request callback.** The raw-file streams piped at `app-shell-routes.mjs:279/290` also have no `error` listener (pipe doesn't propagate; the response hangs). **Fix:** `if (!response.headersSent) sendJson(...) else response.destroy()`; attach stream error listeners.

**F18 — `services/request-context.mjs:11-13`: outside a request, context is `{}`, which `isPrivateBetaSuperuserOrLocal()` reads as "local superuser".** Today no background path calls scoped services (verified: the retry timer touches none), but any future background job inherits full unscoped visibility silently. Also `deterministicUuid` is duplicated between request-context and `runtime-db-matter-index.mjs:218-224` — it is the **join key** for the SQL visibility clause; drift there is an authz bug. (A third copy in the storage service uses version nibble `0x40` vs the index's `0x50` — likely intentional namespacing, but it's invisible duplication either way.) **Fix:** explicit `{ background: true }` context for non-request execution; dedupe the UUID helper.

**F19 — `routes/route-utils.mjs:39-50`: tester scoping keys on matter *names*, not ids.** Nothing enforces name uniqueness across users; two users each with a matter named "Draft" would see each other's jobs/feedback/runs ledger rows. Jobs already persist `matterId` (`job-status-service.mjs:176`). **Fix:** prefer id-based membership, fall back to names only for filesystem-era records.

**F20 — `private-vm-rsync-deploy.mjs:134`: `prepare_release_dir` runs `rm -rf` on the release dir with no guard that it isn't the currently-active release.** Re-running deploy for the same commit (the natural retry after a failed service-check, since the commit comes from HEAD) deletes the live app directory under the running service; if `npm ci` then fails, `current` points at a gutted release. **Fix:** preflight `test "$(readlink -f current)" != releaseDir`, or require `--force` for same-commit redeploys.

**F21 — stale-job sweep × provider timeout interplay.** Only `source_labels` jobs report progress; `extract`/`intake`/`custom_skill` never touch `updatedAt` mid-run, so a legitimately long run gets flipped to `failed` by the 30-minute sweep while alive — and worst-case describe-sources retry math (2 attempts × primary+fallback × 240s default timeout ≈ 16 min) stays under the threshold *only by configuration luck*; raising `OPENROUTER_SOURCE_DESCRIPTION_TIMEOUT_MS` past ~450s breaks it. After `completeJob`, the job reads `succeeded` yet retains the stale-failure `errorMessage` (`job-status-service.mjs:69-84`). **Fix:** heartbeat from long engines; have `completeJob` clear `errorMessage`/`failureClass`; derive (or assert) the sweep threshold against the configured provider timeout.

**F22 — matter folder names ship off-VM in *safe* telemetry mode** (`private-beta-signal-service.mjs:276→:408-416`, `private-beta-feedback-service.mjs:322`). For a legal product, folder names can identify clients ("Smith-v-Jones-…"). Matter *content* is correctly gated behind `firm_internal`, and metrics carry no matter identifiers at all (verified). This is a deliberate named field, not a leak — but it's a product/legal call that should be made explicitly, not inherited.

**F23 — the React component-test layer is regex-over-source and cannot catch behavioral regressions.** E.g. `react-settings-load-guards.test.mjs:25` asserts exact whitespace; `react-private-beta-users-panel.test.mjs:12-18` greps for API call names. None render with `authEnabled: false` — which is exactly why F10 shipped. The visibility contract is also asserted twice against two policy copies with duplicated fixtures (`react-lawyer-mode-visibility` vs `lawyer-mode-visibility`), so twin drift is undetectable by construction. **Fix:** one cross-contract parity test importing both policy modules over a shared path list (~20 lines); longer-term, a render harness (the transpile-and-execute trick in `react-lawyer-mode-visibility.test.mjs:14-21` shows the appetite exists).
