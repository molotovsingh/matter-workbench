## Included Since beta.102

- The runtime DB processing worker now queues the preparation chain after successful upload/extract processing:
  - `source_labels`
  - `case_timeline`
  - `matter_story`
  - `posture_diagnosis`
- Worker follow-up scheduling follows the `/api/prepare-matter` plan and only queues the next needed/currently allowed stage.
- Preparation-chain jobs use stable idempotency keys and metadata so retries do not duplicate already-scheduled stages.
- Follow-up enqueue failures are logged but do not fail the already-completed worker job.
- Upload extract jobs carry `preparationChain` / `preparationChainId` metadata for chain tracking.
- Added migration `025_processing_job_stage_kinds` so `processing_jobs.kind` accepts the backend-owned preparation stage jobs and existing runtime job kinds.
- Added regression coverage for dependency-order queueing, nonfatal follow-up enqueue failures, and the widened job-kind DB constraint.

## Deployment Note

An untagged beta.103 deployment smoke exposed the missing `processing_jobs.kind` constraint update: `case_timeline` could not be recorded until migration 025 existed and was applied. beta.104 is the tagged/release-documented checkpoint that includes that migration and the passing live smoke.

## Not Promised

This release does not make React fully observe backend preparation jobs, add chunked uploads, or retroactively regenerate missing artifacts for old matters without running preparation. It queues the backend-owned post-upload chain for new worker-driven upload processing and keeps the DB schema aligned with those job kinds.

## Operator Notes

Use `v1.0.0-beta.104` for supervised testing. Roll back to `v1.0.0-beta.102` / `a092764` if post-upload preparation queueing or migration 025 causes a regression.
