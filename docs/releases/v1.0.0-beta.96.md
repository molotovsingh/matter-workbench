Codename: **Resume Thread**

## Included Since beta.95

- New Matter and Add Files now remember an unfinished durable upload session in browser local storage.
- On returning to the form, the UI shows an **Unfinished upload session found** card.
- If the user re-selects the same paths and sizes, submit resumes the saved durable session instead of creating a new one.
- Resume skips file indexes the server already received and uploads only missing files.
- Successful commit clears the browser recovery draft.
- Added `POST /api/upload-sessions/:id/cancel`.
- **Forget saved upload** now best-effort cancels the server session and clears staged payload custody.
- Added helper tests for failed upload recovery, same-file matching, missing-file resume, and cancel cleanup.
- Added service/API tests for upload-session cancel.

## Not Promised

This release does not implement true byte-range/chunked upload. Browser refresh still requires the user to re-select the same files, because ordinary browser file inputs cannot preserve file handles across reloads. This release also does not move preparation stages beyond extraction into backend workers.

## Remaining Limits

The first-class durable upload backbone is now visible and recoverable enough for whole-file retry/resume. Future hardening should add chunked upload for very large individual files and move later preparation stages into the runtime DB worker model.

## Operator Notes

Use `v1.0.0-beta.96` for supervised testing. Roll back to `v1.0.0-beta.95` / `f709eaa` if the upload recovery UI unexpectedly affects create/add-files behavior.
