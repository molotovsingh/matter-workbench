# Matter Workbench v1.0.0-beta.5

Date: 2026-06-06

This is the private beta release-candidate closure checkpoint.

It keeps the React-only local/private beta and accepted runtime DB mode from
`v1.0.0-beta.4`, then adds a repeatable release closeout pack that ties local
verification, runtime DB browser acceptance, private VM service health,
operator posture, access/security checks, and recoverability evidence into one
run.

## Release Position

Release as:

```text
v1.0.0-beta.5
```

Meaning:

- the React shell remains the only product UI at `/`;
- filesystem mode remains available for ordinary local beta operation;
- explicit runtime DB mode remains accepted for local/private beta operation;
- private VM operation is still private-network only, not public SaaS;
- release-candidate judgment now has one repeatable closure command:
  `npm run private-beta:rc-closure-pack`.

## Included

- Everything from `v1.0.0-beta.4`.
- Runtime DB browser acceptance pack.
- Intake reliability pack.
- Private beta RC closure pack.
- Updated beta operator checklist pointing to the current release checkpoint.

## Private Beta RC Closure

The closure command:

```bash
npm run private-beta:rc-closure-pack
```

aggregates:

- local verification;
- runtime DB browser acceptance;
- private VM service smoke;
- private VM ops pack;
- private VM access/security check;
- private VM recoverability pack.

The closure pack writes Markdown and JSON evidence under
`.local/private-beta-rc-closure-packs/` by default. It is intentionally an
operator evidence bundle, not a new product feature.

When the private VM does not have a browser automation runtime, use the
Mac-generated runtime browser acceptance JSON with
`--runtime-browser-evidence-json`. That keeps the release evidence complete
without pretending a skipped browser gate passed.

## Not Promised

This release does not promise:

- public hosted SaaS deployment;
- HTTPS/TLS termination;
- multi-user hosted auth/session middleware;
- cloud object storage;
- durable background workers that survive browser/process shutdown;
- unsupervised legal reliance;
- perfect OCR on bad scans;
- final court-ready drafting.

The exact claim is narrower: Matter Workbench is ready as a supervised
local/private beta release candidate when the closure pack passes on the target
machine and the operator accepts the listed risks.

## Release Judgment

This is the right checkpoint to stop treating beta readiness as scattered
manual confidence and start treating it as a repeatable operator pack.

Future work should split cleanly:

1. supervised beta bug fixes and legal-quality polish;
2. private deployment hardening;
3. hosted auth, object storage, background workers, and rollback policy.
