# Matter Workbench v1.0.0-beta.7

Date: 2026-06-07

Codename: **Docket Ember**

This is the durable job-status first-slice checkpoint.

It keeps the React-only local/private beta, runtime DB storage mode, private VM
service pack, and private beta evidence packs from `v1.0.0-beta.6`. The new
slice adds a local job-status ledger and Activity-page surface for long-running
work, so matter preparation and custom skill attempts leave a durable record of
what ran, whether it succeeded, and why it failed.

## Release Position

Release as:

```text
v1.0.0-beta.7
```

Meaning:

- the React shell remains the only product UI at `/`;
- long-running matter workflow calls now attach a `job` status object to the
  API response;
- `/api/jobs` exposes the local job-status ledger for Activity and diagnostics;
- Activity now separates operational job status from custom-skill output
  receipts;
- runtime DB mode remains a local/private beta storage mode, not hosted SaaS;
- hosted background workers remain future work.

## Job Status vs Skill Receipts

The new job ledger answers:

```text
Did the long-running operation run, and what was its state?
```

The custom-skill receipt ledger still answers:

```text
What output did this skill produce, and can the active matter open it?
```

Those are intentionally different records. A failed preparation stage may have
no legal output but still needs durable operational evidence. A completed skill
run may have a receipt and output files even if the broader job/status surface
is later filtered or archived.

## Not Promised

This release does not promise:

- a hosted background worker queue;
- resumable jobs after process shutdown;
- cross-host job recovery;
- Postgres `processing_jobs` as the live application source for this ledger;
- public hosted SaaS deployment;
- unsupervised legal reliance.

The exact claim is narrower: the local/private beta now records and displays a
durable, redacted job trail for important long-running app operations.

## Operator Notes

Use Activity when a tester says a run "skipped," "hung," or "failed." The
`Matter Jobs` section shows operational state. The existing run receipt cards
still show custom-skill output status.

For one-bug handoff evidence, keep using:

```bash
npm run private-beta:bug-evidence-pack -- \
  --base-url http://127.0.0.1:4191 \
  --matter "Matter Name" \
  --note "Short bug description"
```

After trusted-tester handoff, use the
[Private Beta Bug-Fix Loop](../private-beta-bug-fix-loop.md): fix reported beta
defects narrowly, preserve evidence, and avoid using the beta window as a new
feature sprint.

If a future hosted worker or runtime DB job queue is implemented, this release
note should be treated as the local UI/status-contract predecessor, not proof
that hosted job execution already exists.
