# Matter Workbench v1.0.0-beta.27

Date: 2026-06-24

This is a narrow Beta 3 upload visibility release. It follows the beta.26
browser-upload hardening by making upload failures observable before a matter
exists and by showing the selected upload batch size on the New Matter page.

## Release Position

Release as:

```text
v1.0.0-beta.27
```

Tag target / deployed commit:

```text
e2ac30c Show new matter upload batch size
```

The tag points to the exact code installed on the DigitalOcean beta VM.

Meaning:

- Beta 3 remains the accepted private-cloud beta line;
- this marker is a Beta 3 bug-fix / observability release, not a new product
  surface;
- the deployed product remains the React-only private beta with runtime DB
  storage;
- upload submit failures on New Matter and Add Files now emit a safe private
  beta client signal even when the browser fails before the server can create a
  workflow job;
- New Matter now shows selected file count and total upload size before submit.

## Included Since beta.26

Upload observability and tester-facing clarity:

- added safe client-side upload submit failure capture for New Matter;
- added safe client-side upload submit failure capture for Add Files;
- classified these signals under the upload stage without leaking filenames,
  relative paths, or raw browser error text;
- kept the lawyer-facing error copy plain and upload-specific;
- added selected upload batch size to the New Matter file list summary;
- added regression tests for the upload telemetry helper and batch-size display.

## Not Promised

This release does not make large browser uploads resumable or parallel. It does
not replace the planned first-class intake service. It only makes the existing
browser upload path clearer and easier to diagnose when failure happens before a
server-side job exists.

## Operator Notes

If a tester still reports upload failure after this release:

1. check whether the visible page shows the selected upload size;
2. check System Health / operator telemetry for an upload submit failure signal;
3. separate browser submit failure from later preparation or extraction failure;
4. if rollback is needed, deploy the previous product release `43b7d8d`.
