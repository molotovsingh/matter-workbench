# Matter Workbench v1.0.0-beta.55

Date: 2026-06-26

This is a Beta 3 Matter Log foundation release. It adds a read-only, clearly
labeled Matter Log preview projected from existing ledgers, while keeping file
removal blocked behind future custody work.

## Release Position

Release as:

```text
v1.0.0-beta.55
```

Tag target / deployed commit:

```text
b45127d Add read-only Matter Log preview
```

The tag points to the exact code installed on the DigitalOcean beta VM.

## Included Since beta.54

Matter Log foundation:

- adds `GET /api/matter-log` returning `matter-log/v0-readonly`;
- adds `services/matter-log-service.mjs` to project existing job-status and
  configurable-skill-run ledgers into read-only log entries;
- shows a conservative `Matter Log` / `Preview` section on the Activity page;
- labels entries as `projection`, not canonical custody events;
- keeps Copilot receipts and conversation memory out of evidence treatment;
- documents and tests the current matter mutation inventory.

File-removal safety posture:

- keeps ordinary file deletion out of scope;
- keeps `Remove from active record` blocked behind future canonical events,
  tombstones/suppression, active source set projection, artifact currentness,
  and restore/quarantine design;
- updates the Matter Log design note to state that the current implementation is
  only a narrow Phase 3 preview slice, not an accepted event contract.

## Not Promised

This release does not add file removal, tombstones, restore/quarantine,
canonical matter events, a Postgres `matter_events` table, an outbox, artifact
currentness projection, or a broker/Kafka path. The Matter Log is a best-effort
read-only projection only.

Conversation memory and Copilot receipts remain non-evidence.

## Operator Notes
