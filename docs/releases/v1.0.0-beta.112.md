## Included Since beta.111

- Fixed backend-owned needed-preparation jobs so a stale Matter Story queue item carries overwrite metadata and actually refreshes the existing Story artifact.
- Applied the same stale-overwrite metadata path to stale Filing and Procedural Posture Diagnosis queue items.
- Propagated preparation-stage metadata through both manual **Run needed preparation** queue requests and chained post-upload preparation jobs.
- Updated runtime worker Story/posture handlers to honor stale-overwrite metadata.
- Fixed Matter Overview headline logic so a runnable upstream stale step is shown as **Needs update** / **Needs preparation**, not as terminally **Blocked** merely because a downstream step is blocked.
- Updated Matter Overview summary copy to explain that **Run needed preparation** will refresh the next required step and continue as downstream stages unblock.

## Behavior

When Case Timeline changed after The Story was written, Matter Overview should now show the preparation card as updateable rather than terminally blocked. Running needed preparation should refresh The Story with overwrite permission, then allow procedural posture diagnosis to queue/run after the Story becomes current.

The downstream posture row may still show **Blocked** before the Story refresh completes, but the overall card should direct the tester to run needed preparation rather than implying no progress is possible.
