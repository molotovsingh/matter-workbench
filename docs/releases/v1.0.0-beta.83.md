# Matter Workbench v1.0.0-beta.83

Date: 2026-06-29

Codename: **Error Firewall**

This is a trust-boundary hotfix on top of beta.82. It centralizes user-facing AI/provider error sanitization so provider account failures remain visible as Assistant unavailability, without leaking backend/provider wording into API responses or command activity.

## Release Position

Release as:

```text
v1.0.0-beta.83
```

Tag target / deployed commit:

```text
2b6f2a3 Harden user-facing AI error boundary
```

The tag points to the exact code installed on the DigitalOcean beta VM.

## Included Since beta.82

- Added shared user-facing AI error policy helpers.
- Routed server-level status-coded AI/provider errors through that policy.
- Mapped unsafe provider/account/model/quota details to:

```text
Assistant is temporarily unavailable. You can continue using the workspace.
```

- Replaced unsafe user-facing API codes such as `provider.error` with:

```text
assistant.unavailable
```

- Kept diagnostic provider/job codes available in internal telemetry/job records where they are needed for operators.
- Added user-facing error formatting for command/intent-check activity paths.
- Fixed a resume-only matter guard that could leave Ask stuck on “Reading the current matter record…” after an Assistant failure.
