# Matter Workbench v1.0.0-beta.58

Date: 2026-06-26

This is a Beta 3 active-source-set foundation release. It adds read-side source
suppression for future matter-custody workflows, without adding file removal UI,
source-removal writes, restore/quarantine workflows, or physical deletion.

## Included Since beta.57

Active source-set suppression foundation:

- adds `services/active-source-set-service.mjs`;
- defines the optional local suppression manifest
  `.matter-workbench/source-tombstones.json` with schema
  `matter-source-tombstones/v1`;
- recognizes `removed_from_active_record`, `quarantined`, `deleted_pending`, and
  `deleted` as suppressing statuses;
- keeps suppression metadata identifier-only and out of source text / work
  product storage;
- documents the read-side contract in
  `docs/contracts/active-source-set-and-suppression.md`.

Read-side wiring:

- Matter Context packets exclude suppressed sources from file registers,
  source descriptors, sources, and evidence blocks;
- extraction skips suppressed File Register rows before processing;
- Source Index generation skips suppressed extraction records;
- List of Dates generation skips suppressed source records before chronology AI
  input;
- runtime DB workspace and payload reads filter `deleted_pending` source
  documents;
- runtime DB matter-context packets suppress inactive File Register rows.

Safety posture:

- no source-removal write path is added;
- no lawyer-facing remove/delete UI is added;
- no physical purge behavior is added;
- `FILE-NNNN` ids remain stable and are not renumbered;
- future source-file removal remains blocked behind canonical source-custody
  events, atomic tombstone/status writes, active source-set currentness, restore
  and quarantine semantics, and privilege-safe Matter Log summaries.
