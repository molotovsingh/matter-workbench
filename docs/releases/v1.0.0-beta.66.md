# Matter Workbench v1.0.0-beta.66

Date: 2026-06-27

This is a Beta 3 matter-lifecycle release. It adds a non-destructive archive / reopen workflow so closed matters leave active work without deleting source files, generated artifacts, file IDs, or history.


The tag points to the exact code installed on the DigitalOcean beta VM.

## Included Since beta.65

Matter lifecycle:

- adds `POST /api/matters/archive`;
- adds `POST /api/matters/reopen`;
- adds `GET /api/matters?includeArchived=1` for active + archived matter lists;
- hides archived matters from the default active matter list;
- prevents opening an archived matter until it is reopened;
- adds sidebar `Archive` / `Confirm archive` action for the active matter;
- adds Active / Archived tabs in the matter finder;
- lets archived matters be reopened if the client returns.

Storage behavior:

- runtime DB mode uses existing `matters.status` and `archived_at` fields;
- local filesystem mode writes `.matter-workbench/matter-lifecycle.json`;
- no source bytes are deleted;
- no generated artifacts are deleted;
- no `FILE-NNNN` identities are renumbered or removed;
- existing source history remains available for reopening and future retention workflows.

Safety posture:

- this is not permanent deletion or purge;
- no source-file deletion workflow is added;
- no matter purge workflow is added;
- archived matters remain recoverable by reopening;
- permanent deletion remains a future retention/legal-hold workflow, not a normal user action.

## Not Promised
