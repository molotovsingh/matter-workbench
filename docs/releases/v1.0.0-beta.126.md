## Included Since beta.125

- Raises the MW List of Dates provider output budget for the row-level selector.
- Keeps the beta.125 row-level contract:
  - each generated MW List row cites exactly one Case Timeline row;
  - broad date-range / phase summary rows are rejected;
  - substantial Case Timelines must not collapse into a four-row executive summary;
  - source labels in Markdown table cells use readable separators, not skipped HTML breaks.
- Preserves MW List boundaries:
  - it still transforms/selects from Case Timeline rows only;
  - it remains manual, diagnosis-gated, versioned, source-mapped, and not court-facing;
  - internal `FILE-*` and `CT-*` handles remain hidden from default Markdown and retained in JSON/receipts for audit.

## Behavior

The specific bad pattern corrected by this release is an MW List row that cites many Case Timeline rows across many dates, for example:

```text
2010-09-08 — Transaction opened ... followed by allotment, repeated payments, later demands, disputes...
```

That kind of row is now invalid. A valid MW List row must be anchored to one Case Timeline row and one dated event. The selector may still choose the legally most useful subset, but it cannot turn a long source chronology into a few broad narrative buckets.

## Not Promised

This release does not create a court-facing filing List of Dates, SLP chronology, writ chronology, or export profile. MW List of Dates remains MW-authored working analysis for lawyer review.

This release does not make MW List of Dates automatic preparation. It does not silently proceed on unconfirmed procedural diagnosis. It does not reopen raw source documents or run legal research inside MW List of Dates V1; the workflow transforms selected Case Timeline rows.

This release does not migrate or rename historical runtime DB storage object keys. Existing legacy Case Timeline storage keys are still display-mapped by beta.124 behavior.

Ask remains matter-record-only. Statutes and public law remain Research-only.
