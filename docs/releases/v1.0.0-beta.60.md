# Matter Workbench v1.0.0-beta.60

Date: 2026-06-26

Codename: **Inactive Seal**

This is a Beta 3 runtime DB active-source foundation release. It adds source
document inactive-status vocabulary and aligns runtime DB read filters with the
active-source suppression contract, without adding file removal UI or a
source-removal write path.

## Included Since beta.59

Runtime DB source status foundation:

- adds migration `021_source_document_active_statuses`;
- extends `documents.status` to allow inactive active-record states:
  `removed_from_active_record`, `quarantined`, `deleted_pending`, and `deleted`;
- adds an index for tenant/matter/status/file-id source status reads;
- updates runtime DB workspace, payload, and upload-overlap SQL to exclude the
  full inactive status set rather than only `deleted_pending`;
- updates the active-source contract and Matter Log planning note to reflect the
  wider runtime DB inactive-status vocabulary.

Safety posture:

- no source-removal write path is added;
- no lawyer-facing remove/delete UI is added;
- no physical purge behavior is added;
- migration `021` does not delete rows, storage objects, or payload bytes;
- future source-file removal remains blocked behind canonical source-custody
  events, atomic tombstone/status writes, active source-set currentness, restore
  and quarantine semantics, and privilege-safe Matter Log summaries.

## Operator Notes

inactive active-record states without physical deletion. Existing matters behave
as before unless rows are explicitly assigned one of the inactive statuses by a
future controlled mutation. If rollback is needed, deploy `9002bbb` after
reviewing migration rollback implications.
