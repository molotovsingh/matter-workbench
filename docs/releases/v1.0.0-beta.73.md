# Matter Workbench v1.0.0-beta.73

Date: 2026-06-28

Codename: **Custody Lily**

This is a Beta 3 tester-feedback feature release. It adds a legal-safe **Remove from active record** workflow for source files so testers can remove an unwanted file from the active case record without deleting source bytes, file IDs, extraction records, generated artifacts, or event history.

## Release Position

Release as:

```text
v1.0.0-beta.73
```

Tag target / deployed commit:

```text
e74a122 Add non-destructive source removal workflow
```

The tag points to the exact code installed on the DigitalOcean beta VM.

## Included Since beta.72

Tester feedback addressed:

- `feedback_d2ab3b3e-128b-4e65-bc05-fd5a3ebec6a2` — “Please add a feature to delete files from case records”;
- `feedback_d95241fa-2b2c-49b8-8d80-43dd30897de2` — “Delete File feature”.

Changes:

- adds `POST /api/source-removal/remove-from-active-record`;
- routes runtime DB source removal through the DB-native mutation path;
- routes local source removal through `.matter-workbench/source-tombstones.json`, matter events, and artifact currentness markers;
- requires a reason and idempotency key for source-removal writes;
- writes `source_file.removed_from_active_record` event history;
- marks downstream artifacts stale/needs review where applicable instead of regenerating or deleting them silently;
- exposes “Remove from active record” in the file preview panel when a `FILE-NNNN` source ID is visible;
- shows an impact preview and a confirmation panel with explicit non-deletion copy;
- refreshes the active workspace after removal so the source disappears from the active record.

## Not Promised

This release does not add permanent file purge, physical deletion of source bytes, legal-hold review, export-before-purge, retention-policy automation, restore/quarantine UX for individual source files, Google Drive import, larger upload limits, image OCR, Word-document extraction, or automatic regeneration after removal.

A future destructive purge, if ever added, must remain a separate retention/legal-hold/export workflow.

## Operator Notes

Use “Remove from active record,” not “delete,” when explaining this to testers. The file is suppressed from active case context and workspace reads, but custody material is intentionally preserved for auditability.
