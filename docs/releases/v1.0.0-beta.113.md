## Included Since beta.112

- Added the native built-in `/procedural_posture_diagnosis` skill stub for **Filing and Procedural Posture Diagnosis**.
- Registered the skill in the built-in skill registry and shared slash-command metadata.
- Added native command aliases such as “procedural posture”, “diagnose procedural posture”, and “posture diagnosis”.
- Added React native-command metadata so the command palette routes diagnosis directly rather than treating it as a configurable custom skill.
- Wired the app shell to call the existing procedural-posture backend route and open `20_Workshop/Case Analysis/Filing and Procedural Posture Diagnosis.md` when ready.
- Added guarded replacement behavior: an existing diagnosis is kept unless the user confirms replacement, with lawyer-review and paid-capacity copy.
- Updated Skills page labels and tests so the built-in appears under Case Analysis / Analyze governance instead of user-editable custom-skill configuration.
- Recorded the Preparation Planner V2 / diagnosis robustness future-design plan for the next preparation architecture slice.

## Behavior

The diagnosis remains an app-owned legal-analysis workflow, not a user-configurable skill. Testers can invoke it from Skills, slash command, or native aliases, and Matter Workbench runs the existing backend diagnosis path with the same saved artifacts:

```text
20_Workshop/Case Analysis/Filing and Procedural Posture Diagnosis.md
20_Workshop/Case Analysis/Filing and Procedural Posture Diagnosis.json
20_Workshop/Case Analysis/Case Analysis Q&A.md
```

If a prior diagnosis artifact exists, the native command first asks before replacement. Cancelling keeps the existing artifact and does not start a paid Assistant run.
