## Included Since beta.126

- Rebuilds MW List of Dates Markdown into:
  - **Chapter 1 — Working List of Dates**: the lawyer-facing chronology first;
  - **Chapter 2 — Basis, Assumptions, and Review Notes**: working legal frame, how to read, difficult facts, facts not emphasized, missing material, review checklist, and audit note.
- Makes Chapter 1 subtly client-oriented while preserving evidentiary discipline:
  - respondent allegations remain allegations/assertions;
  - disputed facts remain disputed;
  - final-finding language such as illegal/fraudulent/mala fide is prohibited unless sourced as an allegation.
- Normalizes lawyer-visible Date column values to Indian numeric format `DD/MM/YYYY`.
- Strips repeated leading dates from event text where the date already appears in the Date column.
- Formalizes common source labels in Markdown, including normalized `DD/MM/YYYY` dates, while preserving raw source labels and internal handles in JSON/receipts.
- Keeps beta.126 row-level MW List constraints:
  - each generated MW List row cites exactly one Case Timeline row;
  - broad date-range / phase summary rows are rejected;
  - substantial Case Timelines must not collapse into a tiny executive summary.

## Behavior

The MW List is now structured as a working client chronology first, not a memo whose chronology appears after the reasoning. The default visible flow is:

```text
# MW List of Dates
metadata

## Chapter 1 — Working List of Dates
table: Date | Event | Relevance for the client's case | Source

## Chapter 2 — Basis, Assumptions, and Review Notes
working legal frame, difficult facts, missing material, review checklist, source audit note
```

This is still not a court-facing filing copy. It is a lawyer-review draft that builds the case theory more clearly while preserving source discipline and adverse-fact handling.

## Not Promised

This release does not create a court-facing filing List of Dates, SLP chronology, writ chronology, or export profile. MW List of Dates remains MW-authored working analysis for lawyer review.

This release does not make MW List of Dates automatic preparation. It does not silently proceed on unconfirmed procedural diagnosis. It does not reopen raw source documents or run legal research inside MW List of Dates V1; the workflow transforms selected Case Timeline rows.

This release does not migrate or rename historical runtime DB storage object keys. Existing legacy Case Timeline storage keys remain display-mapped by beta.124 behavior.

Ask remains matter-record-only. Statutes and public law remain Research-only.
