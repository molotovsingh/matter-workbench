# Matter Workbench v1.0.0-beta.4

Date: 2026-06-06

This is the local/private runtime DB cutover checkpoint.

It keeps the React local beta product from `v1.0.0-beta.3`, then adds the
first accepted runtime DB mode: Postgres can now serve matter selection,
uploads, workspace/file reads, file payload custody, status/advisory reads,
skill-factory state, custom-skill run receipts, command interaction history,
and foreground workflow writes through the materialized runtime bridge.

## Release Position

Release as:

```text
v1.0.0-beta.4
```

Tag after the runtime DB cutover branch lands on `main`:

```text
v1.0.0-beta.4
```

Accepted app baseline:

```text
1b9c6a3 Prove runtime DB write cutover
```

Meaning:

- the React shell remains the product UI at `/`;
- filesystem mode remains the default local beta mode;
- explicit runtime DB mode is now accepted for local/private beta operation;
- runtime DB mode must use `MWB_RUNTIME_DB=postgres`,
  `MWB_RUNTIME_DB_STORAGE=postgres`, and
  `MWB_DB_RUNTIME_CUTOVER_APPROVED=yes`;
- the runtime should use `MWB_RUNTIME_DATABASE_URL` with a normal PostgreSQL
  role, not an admin/superuser URL;
- hosted multi-user deployment, cloud object storage, and DB-claimed worker
  recovery remain separate deployment work.

## Product Spine

The legal workflow spine is unchanged:

```text
new/import matter
-> prepare matter
-> extract source records
-> create Source Labels / Document Index
-> create List of Dates
-> inspect outputs and matter attention
```

The important native-skill spine remains:

```text
/matter-init -> /extract -> /describe_sources -> /create_listofdates
```

What changed is the storage authority available behind that spine. In normal
local mode, matter folders and JSON ledgers remain the runtime source. In
runtime DB storage mode, the app reads and writes through Postgres payload
custody, while existing engines run against temporary materialized folders.
Those temporary folders are scratch space; Postgres is the accepted custody
source for that mode.

## Included

- React/Vite production shell at `/` and `/react/`.
- Local filesystem beta mode from `v1.0.0-beta.3`.
- Runtime DB matter index and active matter switching.
- Runtime DB uploads and add-files without requiring a live matter folder.
- Runtime DB workspace tree, file preview, and raw file streaming from payload
  rows.
- Runtime DB matter status, prepare plan, and latest advisory reads.
- Runtime DB storage payload custody through `storage_object_payloads`.
- Runtime DB materialized write bridge for matter init, extraction, Source
  Labels, List of Dates, doctor fixes, copilot/context reads, custom skill
  execution, and matter story.
- Runtime DB skill ideas, skill samples, configurable skills, lifecycle state,
  run receipts, and command interaction history.
- Runtime role setup through `npm run db:runtime:role-setup`.
- Live runtime write-smoke through `npm run db:runtime:write-smoke`.

## Not Promised

This release does not promise:

- unsupervised legal reliance;
- final court-ready drafting;
- public hosted SaaS deployment;
- hosted multi-user auth/session middleware;
- cloud object storage;
- DB-claimed background workers that survive browser/process shutdown;
- hosted outage/degraded-mode behavior;
- perfect OCR on bad scans;
- zero preparation warnings.

The precise release claim is narrower and stronger: local/private runtime DB
mode is now proven with live Postgres reads and writes, a safe runtime-role
boundary, transaction rollback proof, and checked-in acceptance evidence.
