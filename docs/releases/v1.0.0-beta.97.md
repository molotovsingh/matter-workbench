# Matter Workbench v1.0.0-beta.97

Date: 2026-06-30

Codename: **Worker Loom**

This release broadens the runtime DB processing worker so it can run more preparation-stage jobs when they are queued.

## Included Since beta.96

- Runtime DB processing worker now discovers supported job kinds instead of hard-coding `extract` only.
- Built-in worker handlers now cover:
  - `matter_init` via `runtimeDbStorageService.initializeMatter()`;
  - `extract` via `runtimeDbStorageService.extractDocuments()`;
  - `source_labels` via `runtimeDbStorageService.describeSources()`;
  - `case_timeline` via `runtimeDbStorageService.createListOfDates()`.
- Worker supports injected stage handlers for future stage ownership.
- Server wires injected handlers for:
  - `matter_story` using the same runtime DB custody overrides as `/api/matter-story`;
  - `posture_diagnosis` using the same runtime DB custody overrides as `/api/procedural-posture-diagnosis`.
- The release does **not** auto-queue new stages. It only makes the worker capable of claiming/running these stage jobs when a future scheduler or operator path queues them.
- Added worker tests for source labels, Case Timeline, and injected stage handlers.

## Not Promised

This release does not yet make the full preparation pipeline server-scheduled. New stages are not automatically enqueued after upload. The current product flow remains unchanged unless a stage job is explicitly queued.

## Remaining Limits

A future scheduler should decide when to enqueue source labels, Case Timeline, Matter Story, and posture diagnosis, and the React UI should become an observer of those backend jobs instead of owning long-running preparation execution.

## Operator Notes

Use `v1.0.0-beta.97` for supervised testing. Roll back to `v1.0.0-beta.96` / `451d7ce` if broader worker stage discovery unexpectedly affects runtime processing.
