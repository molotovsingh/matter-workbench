# Matter Workbench v1.0.0-beta.93

Date: 2026-06-30

Codename: **Upload Beacon**

This is a private-beta hotfix for upload/first-stage observability under flaky client connections. It does not make uploads resumable yet; it ensures interrupted multipart uploads are treated as explicit failed upload attempts instead of silent non-events.

## Release Position

Release as:

```text
v1.0.0-beta.93
```

Tag target / deployed commit:

```text
c06b37f Track interrupted upload attempts
```

The tag points to the exact code installed on the DigitalOcean beta VM.

## Included Since beta.92

- Multipart uploads now listen for request `aborted` and request `error` events before async temp-dir setup.
- Interrupted uploads fail with explicit code `upload.interrupted` and user-safe retry copy.
- The multipart parser is destroyed and temp files are cleaned up on interrupted uploads.
- `/api/matters/new` now records an `upload` job around matter creation uploads.
- `/api/matters/add-files` now records an `upload` job around add-files uploads.
- Upload jobs complete or fail in the same job ledger used by other workflow stages, so operator checks can see upload attempts.
- Regression tests cover completed multipart uploads and interrupted upload rejection/cleanup.

## Not Promised

This release does not implement resumable chunked uploads, background upload workers, or fully durable first-stage processing. It only closes the immediate blind spot where an interrupted upload could leave no clear operator evidence.

## Operator Notes

Use `v1.0.0-beta.93` for supervised testing. Roll back to `v1.0.0-beta.92` / `a253f29` if the upload hotfix unexpectedly affects intake.
