Date: 2026-07-02

Codename: **Posture Latch**

This is a supervised beta bug-fix release for saved Filing and Procedural Posture Diagnosis runs that receive truncated or otherwise invalid JSON from the provider.

## Included Since beta.115

- Retries retryable provider JSON failures once inside each procedural-posture provider stage.
- Covers proposer, critic, and finalizer stages for `provider.invalid_json` and `provider.empty_output`.
- Adds explicit retry instructions asking the model for one complete concise JSON object only.
- Raises retry max output tokens for posture diagnosis stages to reduce repeat truncation.
- Keeps durable runner stage attribution intact if both attempts fail, so Activity and retry UX still point to the failed posture-diagnosis stage.

## Behavior

If the provider returns truncated JSON such as `Unexpected end of JSON input` during saved Procedural Diagnosis, Matter Workbench now retries that provider stage once before failing the audited native-skill run.

If the retry succeeds, the saved diagnosis continues normally. If the retry also fails, the job still fails with the same stable provider error and durable stage receipt, so the existing retry/recovery path remains available.

## Not Promised

This release does not change the legal posture-diagnosis schema, diagnosis prompts, saved-artifact location, Ask/Copilot chat behavior, or provider routing. It only adds one bounded retry for retryable malformed/empty provider JSON within the saved diagnosis pipeline.

## Operator Notes

Use `v1.0.0-beta.116` for supervised testing. If saved diagnosis failures regress, inspect the Activity receipt first; a repeated `provider.invalid_json` after this release means both bounded attempts failed and the normal durable retry path should be used.
