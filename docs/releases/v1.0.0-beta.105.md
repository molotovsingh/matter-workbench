Date: 2026-06-30

Codename: **Queue Helm**

## Included Since beta.104

- Added `POST /api/prepare-matter/run` for runtime DB mode.
- The endpoint reads the current `/api/prepare-matter` plan, selects the first runnable/paid-confirmable stage, and enqueues the matching backend processing job.
- Manual needed-preparation jobs now use durable processing jobs for:
  - `matter_init`
  - `extract`
  - `source_labels`
  - `case_timeline`
  - `matter_story`
  - `posture_diagnosis`
- Active queued/running/retrying jobs are reused instead of duplicated when the same stage is already in progress.
- React **Run needed preparation** now prefers the backend queue in runtime DB mode and polls `/api/jobs` for durable status.
- React keeps the old direct in-browser execution path as a fallback for local/filesystem mode or when the backend queue is unavailable.
- Job status reads now support matter/kind/status filters from the React API client.
- The runtime DB worker can queue extraction after matter setup, extending the preparation-stage mapping beyond the post-upload chain.
- Server worker lifecycle wiring tolerates injected test/fake workers without requiring start/stop methods.

## Not Promised

This release does not remove the local/filesystem direct runner, add chunked uploads, or add a generalized scheduler UI. Full rebuild remains the existing advanced direct path. This release moves the default runtime DB **Run needed preparation** path onto durable backend jobs and keeps polling/observation in React.

## Operator Notes

Use `v1.0.0-beta.105` for supervised testing. Roll back to `v1.0.0-beta.104` / `61269d9` if backend-needed-preparation queueing or React job polling causes a regression.
