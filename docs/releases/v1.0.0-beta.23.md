# Matter Workbench v1.0.0-beta.23

Date: 2026-06-18

This is the Beta 3 operator feedback status-disposition marker. It keeps the
beta.22 bounded `whatHappened` report packet and makes the packet's next action
respect the operator feedback status, so closed rows no longer read as if they
still require reproduction work.

## Release Position

Release as:

```text
v1.0.0-beta.23
```

Tag target / deployed commit:

```text
0d4b81b Make feedback context status-aware
```

Branch documentation commits after `0d4b81b` record this release note and
current-release pointers only; they do not change the hosted product behavior
covered by the beta.23 tag.

Meaning:

- the deployed private beta remains the React-only product UI;
- runtime DB storage remains the accepted hosted-beta path;
- DigitalOcean deployment uses the repeatable `private-vm:rsync-deploy` flow;
- runtime and mothership services are expected to be active;
- operator feedback reports include bounded `whatHappened` context for every
  item;
- closed feedback statuses now produce no-immediate-action next actions in that
  context;
- tester-facing feedback intake is unchanged;
- no automated AI feedback triage is introduced;
- credit metering remains shadow/report-only, with no billing or enforcement;
- no public SaaS signup, self-service billing, or unsupervised legal reliance is
  implied.

## Included Since beta.22

Operator-side feedback report improvement:

- `whatHappened.statusDisposition` is included for report items;
- `reviewed`, `fixed`, `not_reproducible`, and `parked` feedback rows are
  marked as closed in the report packet;
- closed feedback rows get a redacted no-immediate-action next action that
  explains when to reopen;
- active signal and active/needs-evidence feedback rows still keep their current
  runtime-evidence next actions;
- existing triage lanes are preserved for compatibility with report filters and
  historical metrics.
