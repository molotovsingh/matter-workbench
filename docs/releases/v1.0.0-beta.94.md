# Matter Workbench v1.0.0-beta.94

Date: 2026-06-30

Codename: **Intake Spine**

This release changes upload intake from a browser-owned multipart action into a first-class DB-backed intake pipeline for runtime DB workspaces.

## Included Since beta.93

- Added migration `024_first_class_upload_sessions`.
- Upload sessions can exist before file bytes move.
- Added durable `upload_session_items` rows with per-file status, relative path, size, hash, and payload custody.
- Added session-first APIs:
  - `POST /api/upload-sessions`
  - `GET /api/upload-sessions/:id`
  - `POST /api/upload-sessions/:id/files`
  - `POST /api/upload-sessions/:id/commit`
- React new-matter and add-files forms use session-first upload in DB workspace mode, with filesystem fallback preserved.
- Session commit materializes matter/document/storage custody from durable file receipt rows.
- Commit enqueues a durable runtime DB `extract` processing job.
- Added opt-in runtime DB processing worker via `MWB_RUNTIME_DB_PROCESSING_WORKER=1`.
- The beta VM runtime env enables the worker.
- `/api/jobs` now includes runtime DB processing jobs, surfaced as `source=runtime_db`.
- Multipart upload handling carries payload bytes separately from numeric size metadata.
- Regression tests cover migration, session state, API routes, commit SQL, multipart interruption, materializer byte handling, and worker claim/complete behavior.

## Not Promised

This is the backbone cure for request-owned upload intake and first-stage extraction. It is not yet full browser-resumable UX after a page refresh, and it does not yet move source labels, Case Timeline, Matter Story, or posture diagnosis into durable backend workers.

## Remaining Limits

The next hardening slice should add visible active-session recovery/resume controls and eventually chunked upload for very large individual files. Later preparation stages should also move behind the runtime DB worker model.

## Operator Notes

Use `v1.0.0-beta.94` for supervised testing. Roll back to `v1.0.0-beta.93` / `c06b37f` if the session-first intake path unexpectedly affects upload.
