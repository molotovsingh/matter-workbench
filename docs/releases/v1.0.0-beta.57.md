## Included Since beta.56

Canonical custom-skill creation events:

- wires Skill Factory activation to emit `custom_skill.created` after a skill is
  successfully activated from an approved sample;
- appends the event inside the same SQL transaction as the configurable skill
  store write in runtime DB mode;
- appends the event to the local JSONL matter-events fallback after the skill
  store write under the same mutation queue in filesystem mode;
- records a small structured payload: skill id, slash, title, source idea,
  approved sample, version, status, output artifact, target lane, and
  source-backed posture;
- keeps sample markdown, evidence blocks, and matter source text out of the event
  payload;
- keeps failed validation attempts event-silent for now.

Event service hardening:

- adds an embedded `appendEventMutationSql` builder so event inserts can be
  composed inside a caller-owned transaction;
- lets the runtime configurable skill store append extra mutation SQL before its
  final JSON result, preserving one transaction for skill + event writes;
- preserves idempotent `matter_events` behavior via `(tenant_id,
  idempotency_key)`;
- keeps unsafe `source_file.deleted` / `source_document.deleted` vocabulary
  blocked.

Docs and tests:

- updates Matter Log / eventing docs to mark `custom_skill.created` as the first
  implemented canonical event;
- keeps file-removal blockers explicit: source-custody events, tombstones,
  active source set, artifact currentness, restore/quarantine, privilege-safe
  summaries, and idempotent matter/document locking;
- adds service, runtime DB SQL, API, and doc tests for the new event path.

## Not Promised

This release does not add file removal, tombstones, restore/quarantine, artifact
currentness projection, source-custody mutation events, outbox publishing, or
Kafka/broker integration. It records only the first low-risk canonical event for
new custom skill activations.

Conversation memory and Copilot receipts remain non-evidence.
