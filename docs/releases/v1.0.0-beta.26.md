# Matter Workbench v1.0.0-beta.26

Date: 2026-06-23

This is a narrow Beta 3 hardening release for the browser upload failure seen
by a tester while creating a new matter with several large PDFs.

## Release Position

Release as:

```text
v1.0.0-beta.26
```

Tag target / deployed commit:

```text
43b7d8d Harden browser upload failures
```

The tag points to the exact code installed on the DigitalOcean beta VM.

Meaning:

- Beta 3 remains the accepted private-cloud beta line;
- this marker is a Beta 3 bug-fix release, not a new product surface;
- the deployed product remains the React-only private beta with runtime DB
  storage;
- browser uploads now fail closed against the beta upload ceiling even if the
  `/api/config` upload limit has not loaded yet;
- raw browser upload failures no longer surface as `Failed to fetch`; the user
  sees a plain upload-specific retry/split-batch message.

## Included Since beta.25

Upload failure hardening:

- added a browser-side fallback upload ceiling of `96 MB` when config is
  missing or stale;
- kept small uploads allowed under that fallback;
- wrapped FormData upload network failures with stable code
  `upload.network_failed`;
- replaced raw browser `Failed to fetch` text with lawyer-readable upload
  guidance;
- added regression tests for both the missing-config bypass and the raw network
  error message.

## Not Promised

This release does not make large browser uploads resumable or parallel. It only
prevents the known oversized browser submit path from degrading into raw fetch
or gateway failures. Large-matter intake still belongs in the future
first-class intake-service workstream.

## Operator Notes

If a tester still reports upload failure after this release:

1. ask them to refresh the page once so the new bundle is loaded;
2. check whether the visible error is the 96 MB split-batch message, an upload
   network message, or a later preparation/extraction error;
3. treat those as separate layers before changing code.

If rollback is needed, use the ops-pack rollback plan generated for this
release or deploy the recorded rollback candidate `422b706`.
