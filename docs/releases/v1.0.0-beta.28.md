# Matter Workbench v1.0.0-beta.28

Date: 2026-06-24

This is a narrow Beta 3 upload stability release. It keeps the beta.27 upload
visibility work, but closes the specific large-browser-batch path that Shivangi
hit while creating a new matter with six PDFs.

## Release Position

Release as:

```text
v1.0.0-beta.28
```

Tag target / deployed commit:

```text
7fc1146 Cap browser upload batches below server limit
```

The tag points to the exact code installed on the DigitalOcean beta VM.

Meaning:

- Beta 3 remains the accepted private-cloud beta line;
- this marker is a Beta 3 hotfix release, not a new product surface;
- the deployed product remains the React-only private beta with runtime DB
  storage;
- browser uploads now keep the app's 96 MB stability cap even when the server
  upload limit is configured higher for Nginx/runtime handling;
- oversized browser selections fail before submit with a plain user-facing
  message instead of reaching brittle browser/gateway paths.

## Included Since beta.27

Upload stability:

- fixed the New Matter / Add Files browser preflight so it uses the stricter of
  the server upload limit and the browser stability cap;
- added a regression test proving a larger server limit does not raise the
  browser batch cap;
- kept the existing duplicate matter, duplicate path, and upload telemetry
  behavior unchanged.

## Not Promised

This release does not make large browser uploads resumable or parallel. It does
not replace the planned first-class intake service. It deliberately keeps large
intake work behind a clear pre-submit stop rather than pretending the current
browser upload path is suitable for very large legal bundles.

## Operator Notes

If a tester still reports upload failure after this release:

1. check the visible selected upload size on the New Matter page;
2. if the batch is over 96 MB, ask the tester to split the upload into smaller
   chunks for now;
3. check System Health / operator telemetry for upload submit failure signals;
4. separate browser submit failure from later preparation or extraction failure;
5. if rollback is needed, deploy the previous product release `e2ac30c`.
