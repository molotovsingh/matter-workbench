## Included Since beta.113

- Added the native-skill runner substrate for audited long-running built-in skills, including staged jobs, durable receipts, sanitized recovery hints, stale-stage handling, and Activity-visible retry actions.
- Wired `/procedural_posture_diagnosis`, `/the_story`, `/create_listofdates`, and `/describe_sources` through native runner paths while preserving existing route compatibility where needed.
- Added safe scoped job-detail receipts and private-beta metadata-only recovery signals for native skill runs.
- Refined saved Filing and Procedural Posture Diagnosis output so visible Markdown hides internal handles/storage paths while JSON sidecars preserve audit data.
- Clarified the chat-vs-saved boundary: Copilot procedural posture answers remain chat-only, while `/procedural_posture_diagnosis` creates the durable artifact, job, and receipt.
- Added explicit Ask-mode choice copy for procedural posture questions: quick chat answer versus saved procedural diagnosis.
- Preserved explicit slash commands in the assistant box so `/procedural_posture_diagnosis` runs as a native skill even when Ask mode is selected.
- Added targeted preparation stage starts so a user can run needed preparation from a chosen currentness point without forcing unrelated current upstream work.
- Moved Matter Preparation skill actions into the relevant preparation rows, with MECE labels such as **Refresh from Source Labels**, **Refresh from Case Timeline**, **Refresh from Matter Story**, and **Run saved Procedural Diagnosis**.
- Extracted the preparation row-action policy into `react-ui/src/lib/preparationRowActions.ts` so row labels, disabled dependency copy, and saved-diagnosis behavior are easier to test and maintain.

## Behavior

Matter Overview now presents one primary action per preparation row instead of a separate duplicate skill-button strip. The final Case Analysis row uses **Run saved Procedural Diagnosis** / **Refresh saved Procedural Diagnosis** copy to make clear that this is a durable saved run, not a chat answer.

The saved procedural diagnosis card no longer competes with a second run button. When the diagnosis is missing or stale, it points the user to the corresponding Matter Preparation row. When a diagnosis is current but unconfirmed, the card remains the place for lawyer confirmation/correction/not-sure decisions.

Native skill runs for posture, story, Case Timeline, and Source Labels now have auditable runner jobs and receipts. Long-running latency remains expected for complex matters; Activity is the durable place to inspect staged progress, failure class, recovery hint, and retry action.

## Not Promised

This release does not make procedural posture diagnosis lawyer-approved, filing-ready, or a substitute for reviewing source material. It does not make Ask/chat answers durable artifacts unless the user chooses a saved native skill run. It does not add public web access, unsupervised legal reliance, or a self-service hosted SaaS posture.
