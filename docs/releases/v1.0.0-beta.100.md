## Why This Exists

A release badge mismatch was observed across testers. beta.99 fixed the server response by marking `/api/config` as `cache-control: no-store`. beta.100 adds the client-side half so the React app also requests runtime config as uncacheable and with a cache-busting token.

## Included Since beta.99

- React `api.getConfig()` now uses a dedicated fresh JSON path.
- Runtime config fetches now send:

```text
cache: no-store
Cache-Control: no-store
Pragma: no-cache
```

- Runtime config fetch URLs include a throwaway `_mwbFresh` query token.
- Added regression tests covering both sides:
  - server `/api/config` emits `cache-control: no-store`;
  - React `api.getConfig()` uses the fresh/no-store/cache-busting path.
