# Matter Workbench v1.0.0-beta.48

Date: 2026-06-25

This is a Beta 3 provider-policy release. It makes OpenRouter the default route
for Skill Factory and custom-skill AI tasks while preserving explicit OpenAI
Direct overrides.

## Release Position

Release as:

```text
v1.0.0-beta.48
```

Tag target / deployed commit:

```text
aac20aa Default Skill Factory AI tasks to OpenRouter
```

The tag points to the exact code installed on the DigitalOcean beta VM.

## Included Since beta.47

Skill Factory OpenRouter defaults:

- changed default provider for `skill_router` to OpenRouter;
- changed default provider for `skill_design_interview` to OpenRouter;
- changed default provider for `skill_sample_output` to OpenRouter;
- changed default provider for `skill_authoring` to OpenRouter;
- changed default provider for `configurable_skill_run` to OpenRouter;
- kept explicit OpenAI Direct overrides via task-specific `*_PROVIDER=openai-direct` env vars;
- kept List of Dates, Source Descriptors, Copilot Ask/Research, and OCR policies unchanged;
- updated `.env.example`, model-routing docs, and policy tests to reflect the new default.

Default Skill Factory OpenRouter models:


## Not Promised

This release does not migrate OCR, provider-run ledger recording, AI settings,
or startup checks. It only changes Skill Factory/custom-skill model policy
defaults to OpenRouter.

## Operator Notes

If an operator needs the prior OpenAI Direct behavior for a Skill Factory task,
set the specific provider override, for example:

```text
SKILL_SAMPLE_OUTPUT_PROVIDER=openai-direct
SKILL_AUTHORING_PROVIDER=openai-direct
CONFIGURABLE_SKILL_RUN_PROVIDER=openai-direct
```

If Skill Factory routing, sample generation, skill authoring, or custom skill
runs regress, rollback to `bba52fe`.
