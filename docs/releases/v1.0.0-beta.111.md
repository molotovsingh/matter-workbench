## Included Since beta.110

- Canonicalized Case Timeline artifact constants while preserving the existing `10_Library/List of Dates.*` storage paths and `/create_listofdates` route.
- Added canonical Case Timeline dependency-state modules for backend and React preparation/status code.
- Kept old `LIST_OF_DATES_*` and dependency-state exports as compatibility shims for native skill/storage internals.
- Moved Matter Overview, automatic preparation, runtime DB preparation read models, artifact currentness, source-removal currentness, context packet readers, and deployment hydration code to Case Timeline constants where they are product/read-model concerns.
- Added guard tests so preparation/UI code uses Case Timeline dependency-state vocabulary instead of the old List of Dates dependency-state names.
- Fixed Matter Overview preparation rows so blocked/stale stages show their backend reason even when no output document exists yet.
- Changed blocked empty-output copy from the misleading `No output document found` to `Output will appear after earlier preparation steps are current.`
- Tightened procedural-posture blocked reasons so a stale Matter Story says to refresh the Matter Story before diagnosing filing and procedural posture.

## Behavior

Matter Overview now explains why dependent preparation steps are blocked or stale. In the reported scenario where **Write dispute story** needs an update and **Diagnose procedural posture** is blocked, the posture row should no longer look like a missing-output bug; it should explain that the Matter Story must be refreshed first.

This release does not physically rename stored chronology artifacts. The current storage paths remain:

```text

10_Library/List of Dates.json
10_Library/List of Dates.csv
```
