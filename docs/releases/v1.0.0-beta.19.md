# Matter Workbench v1.0.0-beta.19

Date: 2026-06-17

This is the Beta 3 feedback-triage audit marker. It keeps the beta.18
operator triage loop and adds durable, redacted audit metadata for future
feedback status changes.

## Release Position

Release as:

```text
v1.0.0-beta.19
```

Tag target / deployed commit:

```text
3ac94b4 Audit mothership feedback status updates
```

Branch documentation commits after `3ac94b4` record this release note and
current-release pointers only; they do not change the hosted product behavior
covered by the beta.19 tag.

Meaning:

- the deployed private beta remains the React-only product UI;
- runtime DB storage remains the accepted hosted-beta path;
- DigitalOcean deployment uses the repeatable `private-vm:rsync-deploy` flow;
- runtime and mothership services are expected to be active;
- the operator feedback-triage loop can review, filter, mark, and audit
  mothership feedback without changing tester-facing intake;
- no provider calls are required for feedback triage;
- credit metering remains shadow/report-only, with no billing or enforcement;
- no public SaaS signup, self-service billing, or unsupervised legal reliance is
  implied.

## Included Since beta.18

Operator-side feedback-triage audit improvements:

- `feedback update-status` accepts optional `--actor` and `--note` fields;
- status-update notes and actors are bounded and redacted before persistence;
- the mothership feedback JSON payload is patched with:
  - `operatorTriage`: latest status, actor, note, and timestamp;
  - `operatorTriageHistory`: append-only status-change entries;
- mothership markdown reports show the latest status audit details when present;
- report JSON exposes status audit fields for downstream operator tooling.

The operator-only triage design is documented in
[`docs/future-design-decisions/feedback-triage-router-plan.md`](../future-design-decisions/feedback-triage-router-plan.md).

posture. It is a private-cloud beta for trusted testers and supervised
operators.
