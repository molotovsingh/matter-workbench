## Included Since beta.94

- Centralized upload payload-byte coercion in `services/upload-file-payload.mjs`.
- Removed duplicated payload-byte handling from runtime DB session upload and upload materialization.
- Kept the post-beta.94 convention explicit:
  - `payloadBytes` is the file payload;
  - numeric `bytes` is size metadata.
- Commit-time upload-session file objects now preserve that same convention.
- Commit file/path ordering is centralized before materialization.
- Commit reads payload-bearing session items through the existing upload-session read helper instead of a separate ad hoc query.
- Runtime DB processing-job SQL row projections are centralized to reduce drift across enqueue, list, claim, complete, and fail paths.
- Added `test/upload-file-payload.test.mjs` for payload precedence, byte-like copy behavior, and temp-path fallback.

## Not Promised

This release intentionally changes no product workflow. It does not add browser refresh resume UX, chunked upload, or additional backend-owned preparation stages beyond the beta.94 extraction worker.

## Remaining Limits

The durable upload-session backbone remains in place, but active-session recovery/resume UI and chunked upload for very large individual files remain future hardening work.

## Operator Notes

Use `v1.0.0-beta.95` for supervised testing. Roll back to `v1.0.0-beta.94` / `16c3f84` if the refactored upload payload path unexpectedly affects upload behavior.
