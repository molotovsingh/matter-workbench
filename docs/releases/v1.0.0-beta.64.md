# Matter Workbench v1.0.0-beta.64

Date: 2026-06-26

This is a Beta 3 source-removal backend foundation release. It adds non-routed
custody mutation building blocks and privilege-safe Matter Log rendering for the
future `Remove from active record` workflow, without exposing any removal route,
endpoint, or UI.

## Included Since beta.63

Backend-only source-removal foundations:

- adds a non-routed local source-removal mutation service;
- requires `reason` and `idempotencyKey` before any write;
- writes local source tombstones, canonical `source_file.removed_from_active_record`
  matter events, and artifact currentness records under a serialized mutation
  queue;
- writes a local repair state if event/currentness writing fails after a
  tombstone write;
- adds runtime DB transaction SQL that locks matter/document rows, updates
  `documents.status`, appends `matter_events`, and upserts artifact currentness
  in one transaction;
- keeps physical deletion blocked.

Matter Log rendering:

- renders canonical `source_file.removed_from_active_record` events with
  privilege-safe summaries;
- includes file id, actor, reason, and affected-artifact status when present;
- strips source text, extracted evidence blocks, and generated legal work product
  from rendered Matter Log details.

Local currentness foundation:

- adds non-routed `.matter-workbench/artifact-currentness.json` persistence;
- normalizes and upserts currentness records atomically;
- stores identifiers/status metadata only.

Safety posture:

- no source-removal route is added;
- no impact preview endpoint is added;
- no lawyer-facing remove/delete UI is added;
- no restore/quarantine workflow is added;
- no physical purge behavior is added;
- no paid/model artifact is silently regenerated.
