# Matter Workbench v1.0.0-beta.10

Date: 2026-06-07

Codename: **Named Witness**

This is the named-tester-account checkpoint for the private/local beta.

It keeps the product behavior from `v1.0.0-beta.9`: React-only UI,
local/private runtime DB mode, private beta access gate, feedback-first tester
handoff, Activity-based bug intake, rendered browser acceptance tooling,
operator evidence packs, and supervised beta boundaries.

The reason this is a new release marker is operational: the private beta gate
now supports operator-managed named tester accounts. Beta testers no longer need
to share one env-level username and password. The VM release can keep an account
file outside the repo, and the operator can add, list, disable, and verify tester
accounts without changing product code.

## Release Position

Release as:

```text
v1.0.0-beta.10
```

Meaning:

- the React shell remains the only product UI at `/`;
- local/private runtime DB mode remains the accepted beta storage path;
- private beta login supports an operator-managed tester account file through
  `MWB_PRIVATE_BETA_USERS_FILE`;
- `npm run private-beta:users` is the account-management tool;
- Activity feedback remains the normal first intake for confusing, wrong, slow,
  or legally weak behavior;
- `private-beta:bug-evidence-pack` remains the deeper developer handoff tool,
  not the first thing a tester has to understand;
- the RC closure pack default release label matches this release marker;
- the beta remains private-network/supervised beta, not public SaaS.

## Included

- Everything from `v1.0.0-beta.9`.
- Named private beta tester accounts via
  `MWB_PRIVATE_BETA_USERS_FILE`.
- Account management CLI:
  `npm run private-beta:users -- add|list|disable`.
- VM deployment using an account file outside the repo:
  `/home/aks/.config/matter-workbench/private-beta-users.json`.
- Fresh private VM RC closure evidence for the exact beta.10 release commit.

## Not Promised

This release does not promise:

- public hosted SaaS deployment;
- HTTPS/TLS termination;
- self-service signup, password reset, or hosted identity-provider flows;
- cloud object storage;
- hosted durable worker recovery;
- unsupervised legal reliance.

The exact claim is narrower: the current private beta has named tester access,
a VM-proven runtime DB deployment path, and a feedback-first handoff loop for
supervised beta use.

## Operator Notes

Use this tag instead of `v1.0.0-beta.9` for private beta tester handoff.

For tester access on the private VM, keep this runtime setting:

```text
MWB_PRIVATE_BETA_AUTH=required
MWB_PRIVATE_BETA_USERS_FILE=/home/aks/.config/matter-workbench/private-beta-users.json
```

Create or update tester accounts with:

```bash
printf '%s\n' '<temporary password>' | npm run private-beta:users -- add --file /home/aks/.config/matter-workbench/private-beta-users.json --username <tester> --password-stdin
npm run private-beta:users -- list --file /home/aks/.config/matter-workbench/private-beta-users.json
npm run private-beta:users -- disable --file /home/aks/.config/matter-workbench/private-beta-users.json --username <tester>
```

The account file is reloaded on login, so adding, disabling, or changing a
tester account takes effect on the next login attempt. Restart the service only
when changing runtime environment variables such as the account file path
itself.

Before giving the URL to a tester, run the temporary handoff drill for a quick
account/URL spot check:

```bash
set -a; . "$HOME/.config/matter-workbench/runtime.env"; set +a
npm run private-beta:tester-handoff-drill -- --base-url http://127.0.0.1:4191
```

The drill creates a disposable tester, proves login, React root access, matter
listing, feedback intake, feedback sync, and signal listing, then restores the
tester account file and feedback ledger. A failed drill is a handoff blocker.
The RC closure pack now runs this same tester handoff drill as a required
release gate.

Before widening access, rerun:

```bash
npm run private-beta:rc-closure-pack
```

Treat any failed section as a release blocker until it is understood.
