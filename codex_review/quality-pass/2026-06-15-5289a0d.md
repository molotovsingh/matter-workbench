## Evidence And Fixes

### P2 - Validate rollback target release as a release-directory token

`scripts/private-vm-rollback.mjs` requires `--to`, but the value is carried
directly into `targetDir = root + "/" + targetRelease`; that path is then used in
preflight, symlink activation, service check, and UI hardening commands
(`scripts/private-vm-rollback.mjs:68`, `scripts/private-vm-rollback.mjs:75`,
`scripts/private-vm-rollback.mjs:79`, `scripts/private-vm-rollback.mjs:80`,
`scripts/private-vm-rollback.mjs:108`, `scripts/private-vm-rollback.mjs:126`,
`scripts/private-vm-rollback.mjs:145`). The tests prove the happy path and
preflight abort behavior, but do not reject `../`, slashes, or absolute-looking
release names (`test/private-vm-rollback.test.mjs:7`,
`test/private-vm-rollback.test.mjs:60`, `test/private-vm-rollback.test.mjs:91`).

Risk: an operator typo or copied value can point `current` at a directory outside
the intended release set if that directory happens to satisfy the loose preflight
checks. Shell quoting prevents command injection, so this is an operational
integrity issue rather than a shell-injection issue.

Concrete fix: add `normalizeRollbackTargetRelease(value)` and require a simple
release token, for example `^[A-Za-z0-9._-]{7,80}$` plus no leading dot and no
`..`. Use the normalized value in both parser and plan builder. Add tests that
`../old`, `/tmp/release`, `foo/bar`, and `.hidden` are rejected.

### P2 - Keep telemetry retry single-flight until old drains actually finish

`createPrivateBetaTelemetryRetryService.runOnce()` sets `running = true`, races
`drainAll()` against a deadline, and clears `running` in `finally`
(`services/private-beta-telemetry-retry-service.mjs:21`,
`services/private-beta-telemetry-retry-service.mjs:25`,
`services/private-beta-telemetry-retry-service.mjs:26`). The deadline promise
returns `{ completed: false, timedOut: true }` while logging that the drain
continues in the background (`services/private-beta-telemetry-retry-service.mjs:40`,
`services/private-beta-telemetry-retry-service.mjs:46`,
`services/private-beta-telemetry-retry-service.mjs:47`,
`services/private-beta-telemetry-retry-service.mjs:50`). The test explicitly
locks in that a second `runOnce()` after timeout is not treated as
`already_running` (`test/private-beta-telemetry-retry-service.test.mjs:135`,
`test/private-beta-telemetry-retry-service.test.mjs:151`,
`test/private-beta-telemetry-retry-service.test.mjs:153`).

Risk: if a queue operation ignores abort or hangs below the shared sync layer, a
later tick can select the same queued rows and send duplicate remote attempts
while the older drain is still mutating results. The JSON-store mutation queue
reduces local corruption risk, but it does not make remote sync attempts
single-flight.

Concrete fix: split the state into `reportedTimedOut` and `drainInFlight`, or
attach an abort signal all the way into queue operations and only clear
`running` after the old drain settles. If responsiveness is required, report the
timeout while leaving subsequent ticks skipped until the previous drain finishes.

## Themes

Deployment strings need the same normalization discipline as uploaded paths.
The repo is strong at path validation inside product data flows, but rollback
still treats a high-impact release selector as a raw string.

Timeouts need ownership, not just reporting. The telemetry sync layer has a
per-request timeout, and the retry service has a tick deadline, but the outer
deadline currently reports liveness by allowing overlap rather than by
cancelling or retaining single-flight ownership.

Contract duplication is being managed well where tests exist. Upload duplicate
paths, API error codes, runtime DB preparation stages, and release metadata are
all covered across frontend/backend or command/test pairs. Keep adding contract
tests when a string crosses a process boundary.

## Highest-Leverage Fixes

1. Add rollback target-release normalization and rejection tests. This is a small
   command-only hardening fix with a direct deployment-safety payoff.
2. Change telemetry retry to retain single-flight ownership until the old drain
   settles, or pass an abort signal through queue operations and prove no
   duplicate drain can run after timeout.
3. Keep the runtime DB storage service large but test-first. It is doing many
   jobs, but the current tests are now better than a premature split.
